# Meeting Notes

An AI meeting notetaker: open a meeting, get a one-line summary, the decisions, the action items and a searchable transcript, then ask questions and get answers that point to the exact moment they came from.

Inspired by [Fathom](https://fathom.video). Not affiliated with it. I built this as the 8x software engineer assignment, in about a day.

- **Live app:** https://fathom-clone-eosin.vercel.app/
- **Repo:** https://github.com/FarahArifQ/fathom-clone

The live app needs no sign-in. All the meetings in it are fictional seed data.

## What works

- **Landing page.** A short, honest page at `/` that says what the product does and what is different about it, with a preview built from the real seed data. No pricing, testimonials or made-up statistics.
- **Library and search.** At `/library`. Four seeded meetings. The search box matches meeting titles, people and what was said, and shows the matching line with its timestamp.
- **Meeting page.** One-line TL;DR, decisions, key points, action items and chapters, all generated by Gemini from the transcript.
- **Clickable timestamps.** Every timestamp in the summary, action items, chapters and Ask answers jumps to that line in the transcript and highlights it.
- **Action items.** Tick them off and the state is saved. Items with no owner get a "Needs owner" badge.
- **Highlights.** Save a highlight on any transcript line. It shows in the sidebar and in the transcript.
- **Ask.** A chat panel, scoped to the current meeting or to all meetings. Answers come only from the transcript and cite the lines they used. If the answer isn't there, it says so. It is also available on the library page, where it searches across all meetings.

## What I kept, changed and cut

| | Decision | Why |
|---|---|---|
| Kept | Library, then meeting page, then transcript | It's the core loop of the product. |
| Kept | Action items next to the summary | People open a meeting to find out what they have to do. |
| Kept | Ask with citations | An answer you can't check is not worth much. |
| Changed | Summary is a TL;DR, decisions and key points | Fathom repeated the same item in several places. I wanted one place per fact. |
| Changed | Timestamp on every claim | You can verify any line of the summary in one click. |
| Changed | "Needs owner" flag on unassigned action items | In my Fathom test call, several tasks had no owner and nothing pointed that out. |
| Changed | Transcript search sits above the text, with a speaker filter | Fathom's search covers the text it is trying to find. |
| Changed | Transcript scrolls inside its own box, with Expand | An hour-long transcript made the whole page endless. |
| Cut | Recording and capture bot | Not required by the brief, and the time was better spent on what comes out of a meeting. |
| Cut | Zoom, Meet and Teams integrations, CRM | Same reason. |
| Cut | Team calls, deals, alerts, playlists | Not part of the core loop. |
| Cut | Points, popups, sales analytics | Noise. |
| Cut | Sign-in | A signed-out link is easier to review. See the limits below. |
| Cut | Pricing, testimonials, customer logos, fake stats | This is a demo. I won't invent social proof. |

## What I noticed in Fathom

I used the free plan, ran a test call and went through summary, action items, annotations, transcript, Ask and sharing.

- The summary repeats the same point in the key takeaways, topics and action items. I gave each fact one place.
- Action items can come out with no owner and nothing flags it. I added the badge.
- The template picker is a very long list. I'm not sure a new user can choose well from it, so I left it out for now (see next steps).
- The summary toolbar has many small controls with unclear labels. I tried to keep one obvious action per area.

## What is stubbed or fake

- There is no recording bot. Meetings come from `data/seed-meetings.json`.
- The people, companies and conversations are all made up.
- Summaries are generated ahead of time with `npm run generate`. A visitor sees saved results, not a live Gemini call, unless a meeting has no summary yet.
- There are no accounts.

## The long meeting

The brief says the hard case is an eight-person call that runs about an hour. The seed data has one: "Launch Readiness Review: Atlas Release", 8 attendees, 48 minutes.

For that meeting I added chapters, a speaker filter, transcript search, and a transcript that scrolls inside its own box. Ask sends the whole transcript for single-meeting questions, so it doesn't miss things that keyword matching would skip.

The limit: I wrote this transcript, it is not a recording of a real call. Real speech has more overlap, filler and tangents than mine does.

## How the AI works

Gemini is called through its REST API, only from server routes. The key never reaches the browser.

- **Summaries.** One call returns the TL;DR, summary text, action items (with owner and timestamp) and chapters as JSON. I validate it with a zod schema before saving. Invalid output is rejected, not stored.
- **Caching.** A summary is only generated if the meeting has none. After that the saved version is returned.
- **Retries.** Temporary errors (503, 429, network) are retried up to 3 times, waiting about 2, 5 and 10 seconds. If `GEMINI_FALLBACK_MODEL` is set, it then tries that model once. If everything fails, the user sees a plain message and a Retry button.
- **Ask, one meeting.** The full transcript, with speakers and timestamps, goes to the model. If it's too long it is trimmed and the answer says so.
- **Ask, all meetings.** Postgres text search ranks transcript lines and the top ones are sent.
- **Grounding.** The model is told to answer only from the lines it is given. Every citation is checked against the lines that were actually sent. A citation that doesn't match is dropped.
- **Cost control.** Ask has a daily cap, 50 by default, counted atomically in the database. After that it returns a friendly message.

## Architecture

- Next.js (App Router), TypeScript, Tailwind, deployed on Vercel
- Supabase Postgres, accessed only on the server with the service role key
- Tables: `meetings`, `attendees`, `transcript_segments`, `summaries`, `action_items`, `chapters`, `annotations`, plus a small table counting daily Ask usage
- Pages: `/` (landing page), `/library` (meeting list and search), `/meetings/[id]`
- API: `POST /api/meetings/[id]/summarize`, `PATCH /api/action-items/[id]`, `POST /api/meetings/[id]/annotations`, `POST /api/ask`

## Run it locally

You need Node 20 or newer, a Supabase project and a Gemini API key.

1. `npm install`
2. Copy `.env.example` to `.env.local` and fill in the values:
   - `SUPABASE_URL`
   - `SUPABASE_SERVICE_ROLE_KEY`
   - `GEMINI_API_KEY`
   - `GEMINI_MODEL`
   - `GEMINI_FALLBACK_MODEL` (optional, use a different model from the main one)
   - `ASK_DAILY_LIMIT` (optional, default 50)
3. In the Supabase SQL editor, run `supabase/schema.sql`, then `supabase/ask-usage.sql`.
4. `npm run seed` loads the meetings and transcripts. It is safe to re-run.
5. `npm run generate` creates summaries for meetings that don't have one. If one meeting fails it carries on and lists the failures at the end.
6. `npm run dev`, then open http://localhost:3000.

## Security

- The service role key is only used in server code and is never sent to the browser.
- Row level security is on for every table, with no anonymous policies. The browser can't query the database directly.
- Summaries generate only once per meeting, and Ask has a daily cap, so the public link can't run up an AI bill.
- `.env.local` is git-ignored. Only `.env.example` (names, no values) is committed.

## Known limits and next steps

- **Shared state.** There are no accounts, so on the live link everyone sees the same ticked action items and highlights. Next step: sign-in and per-user data.
- **Real capture.** Nothing records a call yet. Next step: a bot or an upload that turns audio into the transcript format the app already uses.
- **Templates.** One summary style only. I would add a small set (project kick-off, one-on-one, stand-up) and suggest one from the meeting type, rather than offer a long menu.
- **Ask and checkboxes.** Ask answers from the transcript only, so it doesn't know which action items you have ticked.
- **Action items.** They are ticked by hand. I would like to detect when a later meeting shows one was done.
